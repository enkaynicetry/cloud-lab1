Cloud Computing

What is cloud computing?

Cloud computing means using computing resources, such as servers, storage, databases and networking, over the internet instead of buying and maintaining your own hardware. A cloud provider runs huge data centers and shares their resources with many customers. You can get what you need in a few minutes, add or remove capacity when demand changes, and pay only for what you use. Because of this, even a small team can build an application that reaches users all around the world.

Five essential characteristics

The U.S. National Institute of Standards and Technology (NIST) describes cloud computing with five key characteristics:

  • On-demand self-service: You can create a server or storage space yourself from a web console, without asking the provider for help.
  • Broad network access: You can reach your resources from a phone, a laptop or another server through the internet.
  • Resource pooling: Many customers share the same physical hardware, and virtualization keeps their data separate.
  • Rapid elasticity: Capacity can grow or shrink quickly, often automatically.
  • Measured service: Usage is measured, so your bill follows what you actually consume.

Example: an online shop on sale day

Situation. A small online shop normally gets about 200 visitors a day. Then a big sale starts, and 50,000 people visit the website in just two hours.

Goal of this example. To see why the cloud is useful when the number of users changes a lot.

Analysis.

  • Without the cloud: The shop has to buy enough servers for the busiest day. If it buys too few, the website crashes during the sale and the shop loses customers. If it buys enough, most of the servers sit idle for the rest of the year, which wastes money.
  • With the cloud: The shop can add more servers just before the sale (rapid elasticity) and remove them when the sale ends. It only pays for the hours it really used them (measured service).
  • Takeaway: The shop no longer pays a big upfront cost for hardware (CapEx). Instead, it pays a flexible cost that grows and shrinks with demand (OpEx).

Cloud Services

Cloud services are usually divided into three service models. The main difference between them is how much you manage yourself and how much the provider manages for you.

IaaS

Infrastructure as a Service

The provider gives you virtual machines, storage and networks. You manage the operating system, the runtime and your applications.

Example: Amazon EC2

Advantage: You get the most control and flexibility.

Disadvantage: You must patch the OS and set up security yourself.

PaaS

Platform as a Service

The provider gives you a managed platform for building and running applications, so you can focus on your code instead of servers.

Example: AWS Elastic Beanstalk

Advantage: Development is faster and maintenance is lighter.

Disadvantage: You have less control over the system underneath.

SaaS

Software as a Service

You use a complete application over the internet, directly in a browser or an app.

Example: Google Workspace

Advantage: There is nothing to install or maintain.

Disadvantage: You can only use the features the vendor offers.

Shared responsibility: who manages each layer?

The table shows who is responsible for each layer of the technology stack in each service model.

Key idea: More managed services generally mean less infrastructure administration for the customer. Notice that the customer is always responsible for their own data and who can access it, even with SaaS.

Example: three ways to start a blog

Situation. A student wants to start a personal blog about technology.

Goal of this example. To compare IaaS, PaaS and SaaS by using the same task, and to see how the advantages and disadvantages of each model affect the choice.

Analysis.

  • IaaS (rent a virtual machine): The student installs a web server and blog software, and also updates the OS and handles security. This gives total freedom to customize the blog, but it takes a lot of time and technical knowledge. It is a good choice only if the student wants to learn how servers work or needs special settings.
  • PaaS (upload the code to a platform): The student writes or customizes the blog code and uploads it. The platform takes care of the server, OS and runtime. The student saves a lot of effort, but cannot change the system underneath. It is a good choice if the student can code and wants to publish quickly.
  • SaaS (use a blogging service): The student signs up and starts writing right away, with no setup at all. However, the blog can only look and work the way the service allows. It is the best choice if the student only cares about writing content.
  • Takeaway: No model is better in every case. The more control you want, the more work you must do yourself. The more you want convenience, the more you accept the provider's limits.

Deployment Models

Service models answer what you get from the cloud. Deployment models answer a different question: who owns and uses the cloud infrastructure.

Public

The cloud is owned by a provider and shared by many customers over the internet.

Example: AWS, Microsoft Azure, Google Cloud

Analysis: It has the lowest cost and the fastest start, but you have less control over how and where your data is stored.

Private

The cloud is used by only one organization, either in its own data center or hosted just for it.

Example: A bank running OpenStack in its own data center

Analysis: You get strong control and easier compliance, but setup and maintenance are expensive.

Hybrid

It combines a private cloud and a public cloud, and data or applications can move between them.

Example: Customer records in a private cloud and the public website in a public cloud

Analysis: It balances security and scalability, but connecting and managing both sides is more complex.

Example: choosing a model for a university

Situation. A university has student grades, which are sensitive, and a public news website, which is not.

Analysis. A public cloud for everything is cheap, but it may break privacy rules for the grades. A private cloud for everything is safe, but expensive for a website that needs to handle traffic spikes. A hybrid cloud solves both problems: grades stay private and the news site runs in the public cloud.

Benefits & Challenges

Cloud computing is powerful, but it is not always the best choice. Here are the main trade-offs.

Benefits

  • Lower upfront cost: There is no hardware to buy.
  • Flexibility: You can scale up or down at any time.
  • Fast deployment: A new server takes minutes, not weeks.
  • High availability: Data centers are spread across many regions.

Challenges

  • Security and privacy: Your data is stored outside your own building.
  • Vendor lock-in: Moving to another provider can be difficult.
  • Unexpected costs: Forgotten resources keep charging you.
  • Internet dependence: No connection means no access.
